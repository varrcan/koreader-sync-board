## Каталоги

Сервер умеет индексировать каталоги с файлами книг. Тогда книга, синхронизированная без
**Отправить метаданные документа** и без статистики, получает название, авторов и имя файла из
своего файла: сервер сопоставляет хеш документа с файлом по тому же partial MD5, который считает
KOReader (сопоставление *Бинарная*), или по MD5 имени файла (сопоставление *По имени*, по
умолчанию в CrossPoint). Названия из метаданных синхронизации и из статистики пользователя
важнее.

Администратор добавляет каталоги на экране **Библиотека** в панели. Путь — абсолютный путь на
сервере; сервер только читает его и никогда туда не пишет. Смонтируйте каталог только для чтения
и укажите путь внутри контейнера:

```sh
docker run -d --name ksb \
  -v ksb-data:/data \
  -v /srv/books:/books:ro \
  -p 8080:8080 \
  ghcr.io/varrcan/koreader-sync-board:latest
```

Пользователю контейнера `65532` (или служебному пользователю бинарника) нужно право чтения
файлов и каталогов.

- **Форматы**: `.epub`, `.fb2`, `.fb2.zip`, `.pdf`, `.djvu`, `.mobi`, `.azw`, `.cbz`. Названия,
  авторы, серия и язык читаются из FB2 (`<title-info>`, в том числе в однобайтовых кодировках
  вроде windows-1251) и EPUB (пакет OPF). Остальные форматы сопоставляются только по хешу и
  имени файла. Файлы и каталоги, начинающиеся с точки, и каталоги `*.sdr` пропускаются;
  символические ссылки внутри каталога не обходятся.
- **Группировка**: файлы с одинаковыми нормализованными названием и авторами (например, FB2 и
  EPUB одной книги) образуют одну книгу библиотеки.
- **Сканирование** запускается при старте, каждые `KSB_LIBRARY_SCAN_INTERVAL` (по умолчанию 6
  часов), после добавления каталога и кнопкой **Сканировать**. Неизменённые файлы (тот же
  размер и время изменения) повторно не читаются.
- **Обложки**: после обхода каталогов сканер один раз читает обложку каждого файла FB2, FB2.ZIP
  и EPUB (и снова — при изменении файла) и хранит JPEG-миниатюру в `covers/` внутри каталога
  данных; в каталоги книг ничего не пишется. Для других форматов и книг без обложки она
  генерируется.
- **Недоступное хранилище**: если каталог не читается или внезапно опустел (отмонтированный
  NAS), его индекс сохраняется, а панель показывает ошибку. Чтобы очистить индекс каталога,
  опустошённого намеренно, удалите каталог в панели.
- **NFS**: монтируйте с `soft` и `timeo`: при hard-монтировании упавший сервер блокирует
  сканирование, пока не вернётся, и другие каталоги в это время не сканируются.

## Метаданные книги

Администратор может исправить книгу библиотеки кнопкой **Метаданные** на её странице: выбрать
совпадение из файлов книги или из онлайн-каталога, проверить форму и сохранить или заполнить
форму вручную. Правки хранятся в базе поверх данных из файлов: файлы никогда не меняются, и
повторное сканирование правки не перезаписывает. Пустое поле скрывает значение из файла. Поле,
равное значению из файла, не сохраняется и продолжает следовать за файлом. **Сбросить к данным
файла** удаляет все правки книги.

- **Каталоги**: FantLab и Open Library работают без настройки. Google Books включается
  переменной `KSB_GOOGLE_BOOKS_API_KEY`. Поиск сначала ищет по ISBN из файлов книги, затем по
  названию и авторам.
- **Сеть**: сервер обращается к каталогам, только когда администратор открывает диалог или
  ищет. Нужен исходящий HTTPS к `api.fantlab.ru`, `fantlab.ru`, `openlibrary.org`,
  `covers.openlibrary.org`, `archive.org` и его поддоменам, а с ключом — к `www.googleapis.com`,
  `books.google.com` и `*.googleusercontent.com`. Если каталог недоступен, диалог сообщает об
  этом и показывает остальные.
- **Кеш**: ответы FantLab и Open Library хранятся в базе 7 дней. Ответы Google Books не
  кешируются.
- **Условия Google Books**: сохранение совпадения из Google Books хранит его данные в вашей базе,
  пока существует правка. За соблюдение
  [Google APIs Terms of Service](https://developers.google.com/terms) отвечает владелец ключа.

## FB2 в EPUB

Кнопка **В EPUB** на странице книги конвертирует файл FB2 или FB2.ZIP. EPUB присоединяется к
той же книге и хранится в `converted/` внутри каталога данных, никогда — в каталогах книг. Он
работает как любой другой файл библиотеки (хеши, прогресс, скачивание), и его байты никогда не
меняются сами по себе, даже если меняется FB2 или конвертер, потому что новые байты означали бы
новый хеш документа. Администратор может удалить результат и конвертировать заново; прогресс
чтения сохраняется. Одновременно идёт одна конвертация, в отдельном процессе, не дольше 5 минут.

## Каталог OPDS

Библиотека доступна и как каталог OPDS 1.2 по адресу `/opds` — для KOReader, CrossPoint и
других OPDS-читалок. В нём все книги (новые первыми), поиск, все файлы книги с форматом и
размером, обложки. Скачанный файл совпадает с файлом библиотеки байт в байт, поэтому прогресс
синхронизируется с той же книгой. Если у книги есть FB2, но нет EPUB, появляется и ссылка на
EPUB: файл конвертируется при первом скачивании и сохраняется, как при конвертации из панели.

В KOReader: вкладка **Поиск** в файловом менеджере → **Каталог OPDS** → меню в заголовке →
**Добавить каталог**, URL `https://<хост>/opds`, ваше имя пользователя и **пароль устройства**
(не пароль панели). Если отозвать устройство, каталог на нём перестанет открываться. Без
библиотеки каталог просто пуст.

Каталог использует HTTP Basic, поэтому по обычному `http://` пароль устройства передаётся
открытым текстом: публикуйте его через обратный прокси с TLS, как и WebDAV.
