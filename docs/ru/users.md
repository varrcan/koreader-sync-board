# Пользователи и устройства

[English](../users.md) | Русский

У каждого человека один **пользователь** с **паролем панели** и сколько угодно **устройств** —
по одному на читалку. У каждого устройства свой пароль: по нему KOReader синхронизирует
прогресс и статистику и открывает каталог OPDS. Пароли разные: пароль устройства не открывает
панель, а пароль панели не работает в KOReader.

## В панели

Каждый пользователь управляет своими устройствами в разделе **Устройства**: добавить
устройство (пароль показывается один раз), выдать новый пароль, отозвать. Пароль панели
меняется в **Учётной записи**, при этом другие сессии пользователя завершаются.

Администраторы управляют пользователями в разделе **Пользователи** (`/admin/users`, на
телефоне — через **Учётную запись**): создать пользователя, выдать новый пароль панели, сменить
роль, отключить или включить, удалить привязку OIDC, удалить. Новые и сброшенные пароли
показываются один раз. Администратор не может применить эти действия к своей учётной записи,
поэтому в панели нельзя запереть последнего администратора.

Сессия панели живёт 30 дней с последнего использования. Cookie сессии получает флаг `Secure`,
когда панель открыта по HTTPS (напрямую или через прокси, который передаёт
`X-Forwarded-Proto: https`); по обычному `http://` в локальной сети всё работает и без него.

## Командная строка

Всё это доступно и в CLI `ksb`, где нет проверок панели: это путь восстановления, когда никто не
может войти. CLI работает с той же базой, пока сервер запущен, и изменения (например,
отозванное устройство) применяются со следующего запроса. С бинарником вызывайте `ksb` вместо
`docker exec ksb /ksb` (см. [Установка](installation.md#бинарник)).

```sh
docker exec ksb /ksb user add alice              # [-role admin|user]; пароля панели пока нет
docker exec ksb /ksb user passwd alice           # один раз выводит новый пароль панели
docker exec ksb /ksb user list
docker exec ksb /ksb user role alice admin       # или user
docker exec ksb /ksb user disable alice          # блокирует все устройства и сессии панели alice
docker exec ksb /ksb user enable alice           # устройства снова работают, старые сессии панели — нет
docker exec ksb /ksb user delete alice           # удаляет устройства, прогресс чтения и статистику
docker exec ksb /ksb user oidc-unlink alice      # удаляет привязку OIDC; привязки видны в `user list`

docker exec ksb /ksb device add alice "Kindle"   # один раз выводит пароль устройства
docker exec ksb /ksb device list alice           # имена, создание и последнее использование, флаг отзыва
docker exec ksb /ksb device revoke alice "Kindle"
```

- `user passwd` выводит сгенерированный пароль `xxxx-xxxx-xxxx-xxxx` и завершает все сессии
  пользователя в панели; пароли устройств не меняются.
- `device add` выводит пароль вида `xxxx-xxxx` (8 случайных символов, удобно набирать на
  клавиатуре читалки). В читаемом виде он не хранится и повторно показан быть не может.
- После `ksb user enable` читалка, которой отказывали, пока пользователь был отключён, может
  получать отказ ещё до 10 минут: работающий сервер помнит отклонённые ключи, а CLI — отдельный
  процесс. Включение пользователя в панели действует сразу.
